# AGENTS.md

Single-page marketing site for WAAPPLY (Arabic service organizing job applications for Europe). Vanilla HTML + CSS + JS, split into small files. No framework, no npm, no build step, no dependencies, no tests.

## Architecture

- `index.html` — all markup only (no inline `<style>`/`<script>` blocks).
- `css/` — `variables.css` (design tokens, single source of truth), `reset.css`, `base.css`, `layout.css` (header/nav/mobile drawer/containers/logo), `components.css` (buttons, FAQ, sticky CTA), `sections.css` (per-section styles incl. footer), `animations.css` (`.reveal`/`.in`, keyframes, `prefers-reduced-motion`), `responsive.css` (the 980px and 600px media queries only), `contact-modal.css` (lead form overlay, states, responsive bottom-sheet on mobile).
- `js/` — plain scripts loaded at the end of `<body>`: `navigation.js` (drawer + scroll-spy + Escape-close + body scroll-lock `.nav-open` + focus trap/restore + aria-hidden on page content while open — also guards focus-restore against the contact modal), `faq.js` (accordion + Enter/Space keyboard support + rAF resize re-measure of the open answer), `countries.js` (single source of truth for the 31 target countries — renders the « التقديم حسب الدول » grid into `.countries-grid` with each `.country-card` carrying `data-country="<ISO code>"`; runs before `animations.js` so the generated `.reveal` cards get staggered in), `animations.js` (ONE IntersectionObserver drives everything: `.reveal`→`.in` scheduling and `[data-stagger]` auto-cascade that fills MISSING `data-delay` on direct `.reveal` children — manual delays always win), `app.js` (global init: header scroll shadow, rAF-throttled), `contact-modal.js` (reusable lead form: opens from any `[data-contact-package]` trigger, reads the trigger's optional `data-country` ISO code and sends it as `country` in the POSTed JSON, validates name/WhatsApp/package, POSTs JSON to a Google Apps Script Web App, shows success/error states with optional WhatsApp follow-up; exposes `window.openContactModal(pkg)` and `window.closeContactModal()`).
- `assets/` — local assets only; currently `logo.svg` (official brand logo, used via `<img src="assets/logo.svg" class="logo-img">` in header and footer — do not recreate an inline/text logo), `wpl.png` (real capture of the interface, used as the hero visual via `<img src="assets/wpl.png" class="hero-image" ...>` — do not convert/compress or swap for another format), and `og-image.jpg`. Country cards render flags from the inline SVG sprite (`#i-flag-*`), not photos. The root-level `logo.svg` is only the untouched original source copy. Fonts come from Google Fonts CDN.
- Head SEO block: canonical is exactly `https://waapply.com/` (no www, no alternate canonicals) — also used in `og:url`, JSON-LD ids/urls and `sitemap.xml`; `robots.txt` references `https://waapply.com/sitemap.xml`. JSON-LD lives in a single `<script type="application/ld+json">` in `<head>` with an `@graph` of Organization / WebSite / WebPage / Service (+2 Offers, MAD) / FAQPage (13 questions mirroring the visible FAQ). Keep structured data in sync with visible content; never add LocalBusiness, Review or AggregateRating (no real-world evidence). No `og:image` until a real PNG/JPG social asset exists (SVG logo is not supported as og:image).
- Page flow (compact single-page structure): skip-link → header/nav → mobile drawer → `<main id="main">` containing hero `#top` → pricing `#pricing` (countries grid `#sectors` with 31 country cards rendered by `js/countries.js`; the paid packages and the 30-day student offer are NOT rendered on-page) → faq `#faq` (13 questions, definition first) → final CTA `</main>` → footer (+ sticky mobile CTA outside main) → contact modal (reusable overlay, lives outside `main`). Conversion CTAs (`[data-contact-package]`) open the contact modal; after successful lead submission, an optional WhatsApp follow-up link is provided. Anchors like `#services`, `#benefits`, `#problem`, `#solution`, `#europe`, `#system`, `#how`, `#disclaimer`, `#who`, `#why` no longer exist — nav and footer link only to `#top`, `#sectors`, `#faq` (the existing `#sectors` id still anchors the countries section; kept to preserve existing links). The countries section is a sub-block inside `#pricing`; each `.country-card` has a flag placeholder `.country-media`, an icon badge `.country-ico`, a title/description, and a CTA via `data-contact-package="info"` plus `data-country="<ISO code>"` using `.btn btn-ghost-light-2 country-cta`. The nav/footer "الخدمات" link points to `#sectors`. Package/pricing data (3 months 1,000 DH / 6 months 1,400 DH / student offer 30 days 500 DH) lives only in `js/contact-modal.js` `PACKAGES`, the JSON-LD Offers and the modal `<option>` list — never rendered as page cards.

## Hard constraints

- MUST keep working when opening `index.html` directly over `file://`: no ES modules (`type="module"`), no bundler, no fetch of local JSON. Scripts stay classic `<script src>` tags.
- Functions called from inline HTML attributes must remain on `window`: `toggleMobileNav()`, `toggleFaq(el)`. Each js file ends with explicit `window.fn = fn;` assignments — keep them when editing.

## Conventions

- Page is `<html lang="ar" dir="rtl">`; copy is Moroccan Darija / MSA. New UI must stay RTL-consistent (e.g., flow-chain arrows use `←`).
- Wrap Latin text, numbers, and prices in `class="latin"` (switches to IBM Plex Sans). Headings use IBM Plex Sans Arabic via `--font-heading` (`h1–h4`, weights 700/600 — the family has no 800; never request `wght@800` from Google Fonts).
- Icons: one family only — Lucide-style outline icons embedded as an inline SVG sprite at the top of `<body>` (`<symbol id="i-*">`, 24×24, stroke-based). Use `<svg class="ic" aria-hidden="true"><use href="#i-name"/></svg>`; base `.ic` lives in components.css (18px, stroke 2, round caps), per-component overrides size/stroke it (benefit 26/30px featured, chips 14px, price checks 11px in a 19px disc, who marks 13px, FAQ plus 13px). Never introduce emojis or Unicode glyphs as UI icons; add new symbols to the sprite only when needed (keep it lean).
- Style exclusively with the design tokens in `css/variables.css` (`--navy`, `--blue`, `--blue-strong`, `--gold-1..3`, `--grad-blue/gold/navy/gold-deep`, `--shadow*`, `--radius*`); never hardcode hex values in other css files. `--blue-strong` exists for small labels on tinted backgrounds (AA); `--grad-gold-deep` is the dark-emerald gradient to use whenever white text sits on a gold surface.
- Motion curves are tokens too: `--ease-entrance` cubic-bezier(.22,1,.36,1) for reveals/drawer/large transforms, `--ease-interact` cubic-bezier(.2,.8,.2,1) for hover micro-interactions (buttons). Never write raw `cubic-bezier(...)` in css files; plain `ease` remains only for color/shadow-only transitions.
- Typography and spacing use the documented scales in `variables.css`: font sizes via `--fs-xs/sm/base/md/lg/xl` (13/14/16/17/17.5/22px) and spacing via `--space-1..10` (4px grid). Deliberately hardcoded: fluid `clamp()` titles, `.price-tag` display sizes, the `.hero-image` max-width, `.btn*` metrics (~51px height is sacred), section rhythm paddings >=44px, and centering shorthands (`margin:0 auto`).
- Radii use the token set `--radius-sm`(12)/`--radius`(18)/`--radius-lg`(24)/`--radius-pill`(100px). Deliberately hardcoded: hairlines 2–3px (nav underline, hamburger), decorative strips `0 0 4px 4px`, geometric circles at `50%` (discs/dots), `.fc-ico` 9px (>2px from nearest step), and the `.hero-image` radius for the hero visual.
- Buttons: the base `.btn` carries `border:1.5px solid transparent` so solid and outlined variants keep the same rendered height (~51px; `.btn-lg` ≈60px) — don't remove it or side-by-side button pairs misalign. Conversion CTAs are full-width via `btn-block`; the country cards align theirs to the bottom with `.country-cta{margin-top:auto}` (cards are flex columns).
- Scroll animations: give new sections/cards `class="reveal"`; the IntersectionObserver in `js/animations.js` adds `.in` on scroll. Optional `data-delay="<ms>"` staggers the `.in` timing via JS (no CSS transition-delay, so hovers stay instant). Grids/cascades: put `data-stagger` on a container and its direct `.reveal` children get incremental delays automatically (default 80ms step; children WITH a manual `data-delay` keep theirs — currently used on `.faq-list` and `.countries-grid`). The hero visual (`.hero-image`) reveals with its `.hero-visual.reveal` ancestor. Preserve the `prefers-reduced-motion` overrides in `css/animations.css`.
- Section rhythm alternates backgrounds to avoid flat runs: light sections sit on `--bg` by default, add class `alt-bg` (→ `--bg2`) for contrast. Primary conversion buttons can take `btn-lg`; on dark sections the secondary button is `btn-ghost-light` (not a second solid).
- Responsive breakpoints live only in `css/responsive.css`: 980px (mobile nav drawer + sticky bottom CTA appear, `body` gains `padding-bottom:78px`) and 600px. Check 980px and 600px when touching layout.

## Gotchas

- All conversion/contact CTAs («ابدأ الآن», package buttons, «تواصل معنا فالواتساب», footer «واتساب», sticky CTA) now open a reusable contact modal via `[data-contact-package]` attribute. Generic CTAs use `data-contact-package="info"`, 3-month package CTAs use `"3months"`, 6-month package CTAs use `"6months"`. The modal collects name/WhatsApp/package and POSTs JSON to a Google Apps Script Web App (`CONTACT_API_URL` in `js/contact-modal.js`). Country-card CTAs carry `data-country="<ISO code>"` (e.g. `DE`); the modal sends it as the `country` field in the JSON (empty `""` for generic CTAs) and the backend (`google-apps-script/Code.gs`) stores the **full Arabic country name** (e.g. `ألمانيا`) in the `Pays` column — the ISO code stays the internal value. The backend validates a non-empty country against the 31 allowed ISO codes and renames a legacy `Secteur` header to `Pays` on first write. After success, an optional WhatsApp follow-up link with a personalized message is provided. Keep messages URL-encoded (`encodeURIComponent`) — never paste raw Arabic into the query string.
- The pricing stats/table are demo data (disclaimed on-page). Don't treat them as real.
- Drawer links and its CTA already close the drawer via inline `onclick="toggleMobileNav()"` in index.html — never ALSO bind click listeners to them in js (the double toggle reopens instantly; this bit once). Related: focus restore on close is deferred one `requestAnimationFrame` frame because Chromium resets a synchronous focus restore when closing over a fragment navigation (`#pricing` etc.). Also: the drawer's focus-restore rAF checks whether the contact modal is open (`#contactModal.cm-open`) and skips restore if so, preventing focus conflicts when the drawer CTA triggers the modal.
- `body{overflow-x:hidden}` is permanent in base.css: computed body overflowX is always `'hidden'`. In programmatic QA, assert overflow via the `body.nav-open` class or `overflowY` — never expect `'visible'`.
- `html` sets `scroll-behavior:smooth`; when driving the page programmatically (Playwright/QA), force `document.documentElement.style.scrollBehavior='auto'` before scripted scrolling, or scrollTo jumps lag behind and reveals/overflow measurements give false results. Raw-load measurements also lie: unrevealed `.reveal` elements inflate overflow counts — scroll through the page first before measuring.
