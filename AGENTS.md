# AGENTS.md

Single-page marketing site for WAAPPLY (Arabic service organizing job applications for Europe). Vanilla HTML + CSS + JS, split into small files. No framework, no npm, no build step, no dependencies, no tests.

## Architecture

- `index.html` — all markup only (no inline `<style>`/`<script>` blocks).
- `css/` — `variables.css` (design tokens, single source of truth), `reset.css`, `base.css`, `layout.css` (header/nav/mobile drawer/containers/logo), `components.css` (buttons, icon system, FAQ, sticky mobile CTA), `sections.css` (per-section styles incl. footer: countries grid, sectors, spontanée), `promo.css` (promo hero: video card, badge, animated metrics counter), `animations.css` (`.reveal`/`.in`, keyframes, `prefers-reduced-motion`), `responsive.css` (the 980px/768px/600px media queries plus min-width 1200px/1600px large-screen rules — also holds the offers-page media queries; note it must be loaded AFTER `offers.css` so its queries win the cascade), `contact-modal.css` (lead form overlay, states, responsive bottom-sheet on mobile), `terms.css` (legal pages: terms + privacy), `offers.css` (free job offers pages: hero/trust, tools bar, offer cards, email reveal, pager, empty state — cards/pager/hero still used by `offers-italia.html` (which has NO tools bar) and by `offers-manufacturing-industry.html`, whose search/filter bar re-activates the retained `.offers-tools`/`.offers-tools-inner`/`.offers-search`/`.offers-selects` rules (they were never deleted, only unlinked) — plus the `.offers-opps` / `.opps-grid` opportunity-card directory block added for `offers.html` — the `.opps-note` extra line is scoped to `.offer-card--europe-manufacturing` and `.offer-card--hospitality-restauration`).
- `js/` — plain scripts loaded at the end of `<body>` in this order: `navigation.js` (drawer + scroll-spy + Escape-close + body scroll-lock `.nav-open` + focus trap/restore + aria-hidden on page content while open — also guards focus-restore against the contact modal), `faq.js` (accordion + Enter/Space keyboard support + rAF resize re-measure of the open answer), `countries.js` (single source of truth for the 12 target countries — renders the « التقديم حسب الدول » grid into `.countries-grid` with 8 cards per page + pagination, each `.country-card` carrying `data-country="<ISO code>"`; runs before `animations.js` so the generated `.reveal` cards get staggered in), `sectors.js` (source of truth for the 11 job sectors — renders the « التقديم حسب القطاعات » grid with photo cards from `assets/images/`; ## Hard constraints

- MUST keep working when opening `index.html` directly over `file://`: no ES modules (`type="module"`), no bundler, no fetch of local JSON. Scripts stay classic `<script src>` tags.
- Functions called from inline HTML attributes must remain on `window`: `toggleMobileNav()`, `toggleFaq(el)`. Each js file ends with explicit `window.fn = fn;` assignments — keep them when editing.

## Conventions

- Page is `<html lang="ar" dir="rtl">`; copy is Moroccan Darija / MSA. New UI must stay RTL-consistent (e.g., flow-chain arrows use `←`).
- Wrap Latin text, numbers, and prices in `class="latin"` (switches to IBM Plex Sans). Headings use IBM Plex Sans Arabic via `--font-heading` (`h1–h4`, weights 700/600 — the family has no 800; never request `wght@800` from Google Fonts).
- Icons: one family only — Lucide-style outline icons embedded as an inline SVG sprite at the top of `<body>` (`<symbol id="i-*">`, 24×24, stroke-based). Use `<svg class="ic" aria-hidden="true"><use href="#i-name"/></svg>`; base `.ic` lives in components.css (18px, stroke 2, round caps), per-component overrides size/stroke it (`.country-ico .ic`/`.sector-ico .ic` 26px, `.sp-fi .ic` 19px, `.spontanee-badge .ic` 15px, `.faq-q .plus .ic` 14px, `.footer-col a .ic` 15px, contact-modal success/error `.ic` 36px). Never introduce emojis or Unicode glyphs as UI icons; add new symbols to the sprite only when needed (keep it lean).
- Style exclusively with the design tokens in `css/variables.css` (`--navy`, `--blue`, `--blue-strong`, `--gold-1..3`, `--grad-blue/gold/navy/gold-deep`, `--shadow*`, `--radius*`); never hardcode hex values in other css files. `--blue-strong` exists for small labels on tinted backgrounds (AA); `--grad-gold-deep` is the dark-emerald gradient to use whenever white text sits on a gold surface.
- Motion curves are tokens too: `--ease-entrance` cubic-bezier(.22,1,.36,1) for reveals/drawer/large transforms, `--ease-interact` cubic-bezier(.2,.8,.2,1) for hover micro-interactions (buttons). Never write raw `cubic-bezier(...)` in css files; plain `ease` remains only for color/shadow-only transitions.
- Typography and spacing use the documented scales in `variables.css`: font sizes via `--fs-xs/sm/base/md/lg/xl` (13/14/16/17/17.5/22px) and spacing via `--space-1..10` (4px grid). Deliberately hardcoded: fluid `clamp()` titles, `.btn*` metrics (~51px height is sacred), section rhythm paddings >=44px, and centering shorthands (`margin:0 auto`).
- Radii use the token set `--radius-sm`(12)/`--radius`(18)/`--radius-lg`(24)/`--radius-pill`(100px). Deliberately hardcoded: hairlines 2–3px (nav underline, hamburger), decorative strips `0 0 4px 4px`, geometric circles at `50%` (discs/dots).
- Buttons: the base `.btn` carries `border:1.5px solid transparent` so solid and outlined variants keep the same rendered height (~51px; `.btn-lg` ≈60px) — don't remove it or side-by-side button pairs misalign. Conversion CTAs are full-width via `btn-block`; the country cards align theirs to the bottom with `.country-cta{margin-top:auto}` (cards are flex columns).
- Scroll animations: give new sections/cards `class="reveal"`; the IntersectionObserver in `js/animations.js` adds `.in` on scroll. Optional `data-delay="<ms>"` staggers the `.in` timing via JS (no CSS transition-delay, so hovers stay instant). Grids/cascades: put `data-stagger` on a container and its direct `.reveal` children get incremental delays automatically (default 80ms step; children WITH a manual `data-delay` keep theirs — currently used on `.faq-list` and `.countries-grid`). Preserve the `prefers-reduced-motion` overrides in `css/animations.css`.
- Section rhythm alternates backgrounds to avoid flat runs: light sections sit on `--bg` by default, add class `alt-bg` (→ `--bg2`) for contrast. Primary conversion buttons are `btn-gold` and can take `btn-lg`; the quiet ghost variant `btn-ghost-light-2` is used for country/sector card CTAs and `btn-outline` as the light secondary CTA on the promo hero (never a second solid gold).
- Responsive breakpoints live only in `css/responsive.css`: 980px (mobile nav drawer + sticky bottom CTA appear, `body` gains `padding-bottom:78px`), 768px and 600px, plus large-screen refinements at min-width 1200px/1600px. Check 980px and 600px when touching layout.

## Gotchas

- All conversion/contact CTAs («ابدأ الآن», package buttons, «تواصل معنا فالواتساب», footer «واتساب», sticky CTA) now open a reusable contact modal via `[data-contact-package]` attribute. Generic CTAs use `data-contact-package="info"`, 3-month package CTAs use `"3months"`, 6-month package CTAs use `"6months"`. The modal collects name/WhatsApp/package and POSTs JSON to a Google Apps Script Web App (`CONTACT_API_URL` in `js/contact-modal.js`). Country-card CTAs carry `data-country="<ISO code>"` (e.g. `DE`) and sector-card CTAs carry `data-sector="<canonical French name>"` (e.g. `Industrie manufacturière`); the modal sends them as the `country`/`sector` fields in the JSON (empty `""` for generic CTAs) and the backend (`google-apps-script/Code.gs`) stores the **full Arabic country name** (e.g. `ألمانيا`) in the `Pays` column — the ISO code stays the internal value, and the sector is stored verbatim under its own `Secteur` column. The backend validates a non-empty country against its allowed ISO codes (the list lives in `google-apps-script/Code.gs`) and renames a legacy `Secteur` header to `Pays` on first write; the front only ever sends the 12 target-country codes. After success, an optional WhatsApp follow-up link with a personalized message is provided. Keep messages URL-encoded (`encodeURIComponent`) — never paste raw Arabic into the query string.
- The pricing stats/table are demo data (disclaimed on-page). Don't treat them as real.
- Drawer links and its CTA already close the drawer via inline `onclick="toggleMobileNav()"` in index.html — never ALSO bind click listeners to them in js (the double toggle reopens instantly; this bit once). Related: focus restore on close is deferred one `requestAnimationFrame` frame because Chromium resets a synchronous focus restore when closing over a fragment navigation (`#pricing` etc.). Also: the drawer's focus-restore rAF checks whether the contact modal is open (`#contactModal.cm-open`) and skips restore if so, preventing focus conflicts when the drawer CTA triggers the modal.
- `body{overflow-x:hidden}` is permanent in base.css: computed body overflowX is always `'hidden'`. In programmatic QA, assert overflow via the `body.nav-open` class or `overflowY` — never expect `'visible'`.
- `html` sets `scroll-behavior:smooth`; when driving the page programmatically (Playwright/QA), force `document.documentElement.style.scrollBehavior='auto'` before scripted scrolling, or scrollTo jumps lag behind and reveals/overflow measurements give false results. Raw-load measurements also lie: unrevealed `.reveal` elements inflate overflow counts — scroll through the page first before measuring.
